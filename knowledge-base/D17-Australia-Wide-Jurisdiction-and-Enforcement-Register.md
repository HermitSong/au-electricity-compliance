# D17 - Australia-Wide Jurisdiction and Enforcement Source Register

## Purpose

This page is the routing control for questions that use phrases such as "across Australia", "all states", "all enforcement", "national", or "the Australian electricity industry". It prevents a National Electricity Market or Victorian answer from being presented as complete Australian coverage.

Read this page before D00 whenever the question requires cross-jurisdiction completeness. D00 contains the chronological case and event index; this page identifies the official series that must be checked to assess completeness.

The machine-readable mirror of the source register is `data/enforcement-source-register.json`. The selected D00 event table can be exported to `data/enforcement-events-selected.jsonl` with `scripts/export-enforcement-events.ps1`.

## 4. Completeness Test for an Australia-Wide Answer

An answer may be labelled Australia-wide only after it records:

1. the activity and participant role;
2. whether the activity is in the NEM, WEM, an NT regulated network, the Pilbara or another isolated system;
3. whether the jurisdiction has adopted the NECF;
4. the state or territory licensing and exemption position;
5. the network, safety, WHS, environment and customer-protection regulators that apply;
6. the latest in-force rule or code and any transition date;
7. the official enforcement or annual-report series checked;
8. any publication gap that prevents a claim of case-level completeness.

## 5. Source-of-Truth Rules

- Use legislation, court judgments, regulator registers and official annual reports for material conclusions.
- Use ombudsman reports as evidence of complaint and systemic-issue patterns, not as substitutes for a regulator or court finding.
- Use media only as a `media-trigger`. Bind any legal conclusion to an official outcome.
- Preserve older cases where they explain a failure mode, but label changed rules, overturned judgments and unresolved proceedings.
- Check live sources before relying on annual prices, penalty units, market caps, fees, code versions or transition dates.
